# 安全：投毒、删除与租户隔离

**研究日期：** 2026-11-01

记忆是 agent 里唯一一个失败会持续的部件。一次糟糕的生成，下一轮就忘了；一条糟糕的记忆，会被检索好几个月。这份文档讲这种持续性变成漏洞的三种方式：**投毒**（写进不该有的东西）、**删除**（没能移除该消失的东西）、**租户隔离**（把东西给了错误的主体）。

统一的主张是：**一个记忆系统是一个有对手的数据库，而对手可以通过和用户相同的通道写入。**

---

## 1. 为什么记忆投毒不是提示注入

这个领域一开始把记忆投毒当作提示注入的特例。它是一个独立的攻击类别，差别在架构上。

| 属性 | 提示注入 | 记忆投毒 |
|---|---|---|
| **攻击窗口** | 一次会话 | 无界 |
| **持续性** | 无——上下文丢掉就没了 | 无限期；跨重启存活 |
| **扩散** | 一段对话 | 每一个未来会话、每一个读这个存储的 agent |
| **可检测性** | 在 transcript 里看得见 | 看不见——它看起来像历史 |
| **移除** | 清空上下文 | 需要先知道它被写进来了 |
| **有效的防御** | 摄取时过滤输入 | 摄取时过滤输入 **加** 写入授权 **加** 来源追踪 **加** 删除 |

区别性的属性是最后一行。提示注入防御本质上是关于**上下文窗口的边界**的：只要能挡住对抗性文本进入提示，你就安全了。记忆投毒打破了这个模型，因为注入在上下文存在*之前*到达，然后在之后的会话里作为*可信内容*被检索出来，而那里没有任何边界检查。

**精确的机制。** 一个从对话里抽取事实的记忆系统，分不清"用户告诉我 X"和"用户让我总结的那份文档说 X"。两者都以文本形式到达；两者看起来都像观察。如果抽取步骤把两者以同样的权威级别写入，第二个就是一个有持久性的注入通道。

---

## 2. 攻击面地图

记忆比 agent 的其余部分有更多互不相同的攻击面，因为它有一条摄取流水线。

**1. 摄取。** 网页、文档、邮件、工具输出、其他 agent 的消息。agent 读到的一切都可能包含指令，而被抽取步骤误当作事实。

**2. 抽取。** 那个决定"这里的事实是什么"的 LLM 本身就是可被操纵的。一段精心构造的文字可以让它吐出一条攻击者选的事实，而不是文本里实际有的事实。这是最少被讨论、也最强大的通道：你不需要文本里含有载荷，只需要让抽取器产出它。

**3. 整合。** 后台的 "dreaming" 批次读很多记忆并重写它们。一个把一条记忆塞进集合的攻击者，可以影响对另外许多条的重写——一串级联，而且更糟，因为它在没人看的离线环境里发生。

**4. 检索。** 进入上下文的投毒内容随后被当作证据。严重程度取决于这条记忆的权威层级：一条被投毒的*指令*就是一次政策变更。

**5. 共享。** 从另一个 AI 服务导入的记忆、共享的团队仓库、克隆的 agent，都带着自己的毒一起走。这是供应链面，也是目前防御最弱的。

**6. 删除。** 不删除本身就是一种漏洞，而且是有法律后果的那一种。

## 3. MINJA：仅查询权限的投毒确立了什么

Dong, S., Xu, S., He, P., Li, Y., Tang, J., Liu, T., Liu, H., & Li, J. (2025).
*Memory Injection Attacks on LLM Agents via Query-Only Interaction*.
arXiv:[2503.03704](https://arxiv.org/abs/2503.03704)。

最重要的结果在设定里。之前的工作假设攻击者能直接写记忆——那是平凡的。MINJA 假设攻击者**只有查询权限**：只能发消息，别的都不能做。攻击靠构造查询，诱使 agent *自己的*记忆写入行为记录下攻击者选定的内容。

报告：在被评估的记忆系统上**注入成功率 98.2%**，在随后的检索触发执行上**76.8%**。这些数字来自作者的评估，应当当作"这一类攻击存在"的证明，而不是逐系统的测量——但这一类是真的，而数字高到设计上的推论毫无歧义。

**为什么它有效。** 一个把记忆当作对话副产品来写的 agent，没有"谁授权了这次写入"的概念。用户的消息和攻击者的消息从同一个通道到达；两者都是"对话"；两者都有资格被抽取。系统在写入路径上没有认证。

**它确立的设计要求。** 每次记忆写入都必须携带导致它的那个主体的身份，而检索路径必须能区分"来自用户的记忆"和"来自用户只是展示给 agent 的内容的记忆"。这恰恰是 Devin、Copilot 和 Claude Code 都带的那条来源字段（[03-agent-native-memory.zh-CN.md](03-agent-native-memory.zh-CN.md) 第 5 节）——而它是为信任设计的，不是为安全设计的，这就是它恰好管用的原因。

## 4. top-k 是一个安全参数

这是检索工作方式的一个被低估的后果。

检索多少条，决定了投毒内容进入上下文的通道有多宽。一个每次查询都检索 50 条的系统，给攻击者 50 个位置去占；检索 5 条就给 5 个。召回与攻击面之间有一个直接的权衡，而它从来没有被当作权衡讨论过。

三个推论。

**更宽的检索不是免费的。** 通常的说法是"上下文更多、答案更好"。安全的说法是"上下文更多、攻击面更大、稀释更严重"。两者都对，而两者都指向更小的 top-k 加更好的排序。这是聚焦提示那个结果（[04-research-architectures.zh-CN.md](04-research-architectures.zh-CN.md) 第 9 节）的另一个论据：300 token 的聚焦提示胜过 113K token 的历史，也就是 300 token 的攻击面胜过 113K token 的。

**检索分数应该带来源，而不只是相关性。** 一条来自不可信来源的高相关记忆，不应该排在一条略低相关但来自可信来源的记忆前面。这要求分数以信任为条件，而几乎没有系统这么做——OpenHands 的 `<UNTRUSTED_CONTENT>` 包装最接近，它标记了整块，但没有参与排序。

**阈值化检索是一种防御。** ACT-R 的规则——只在阈值之上检索，否则失败（[02-cognitive-architectures.zh-CN.md](02-cognitive-architectures.zh-CN.md) 第 2 节）——意味着系统返回空，而不是返回一堆坏结果里最好的那个。在投毒下，"一堆坏结果里最好的那个"恰恰是攻击者想要的。

## 5. 什么防得住，什么防不住

MPBench（arXiv:[2606.04329](https://arxiv.org/abs/2606.04329)）是这份文献里最有用的安全结果，而它的头条发现是否定的：在被评估的记忆系统上，**平均攻击成功率 50.46%**，而且**提示注入的防御不能迁移过来**。

最后那句是要紧的，值得从机制上说明为什么。提示注入防御靠匹配输入里像指令的内容（"忽略之前的指令"、角色标记、覆盖短语）。记忆投毒的载荷不像指令，它像一个事实："部署密钥存在 /etc/keys"或者"用户偏好 npm"。没有模式可匹配，因为载荷的全部设计就是与合法内容不可区分。

所以有效的防御是结构性的，不是词法性的：

**每条带来源。** `[source: URL; added: date]`。按设计它不是一个安全特性，但它是让记忆可核验的唯一东西。

**检索时包裹为不可信。** OpenHands 把两个注入的索引都包在 `<UNTRUSTED_CONTENT>` 里并带明确警告。这不阻止投毒；它改变内容到达之后模型对待它的方式。

**引用校验。** Copilot 在送出每条记忆之前，拿它的引用去当前分支校验。这是可验证的真值维护，也是生产环境里最强的结构性防御——一条证据已经不存在的记忆不会被送出。

**写入授权。** 只有根 agent 可以调 `store_memory`；带 `read_memories` 的子 agent 只能读（Copilot）。这把任何单个组件被攻破的爆炸半径限制住了。

**投票与过期。** Copilot 的"有用/没用"加 90 天默认过期，意味着一条从未被验证的投毒记忆会衰减掉。慢，但是真的。

**整合要人批准。** Gemini CLI 的 Auto Memory 和 Antigravity 的 `/learn` 提出 diff 而不是直接写——唯一让人能在一次投毒整合落地之前看见它的设计。

**明确说不管用的。** 输入净化和提示加固。它们对提示注入是必需的，对记忆投毒是不充分的，因为载荷是内容形状而不是指令形状。任何依赖"识别攻击模式"的防御，都会在一个模式是"一句看起来合理的话"的攻击面前失败。

## 6. 删除

本文档里最难的问题，也是唯一有法律后果的。

**为什么难。** 一条记忆至少存在于四个地方，从其中一个删除不等于从其余删除：

1. 派生存储里的**行**
2. 近似最近邻索引里的**向量**
3. 索引结构里的**图邻域**
4. **事件日志**和任何**备份**

删掉行是容易的部分。向量还留在 HNSW 图里作为搜索仍会经过的墓碑。图结构仍然编码着它与其他条目的邻近关系。日志和备份里还有它。

**Ghost Vectors。** arXiv:[2606.18497](https://arxiv.org/abs/2606.18497) 是把这个从理论变成测量的结果：从**软删除**的嵌入里，作者恢复了 **25.5% 的人名**。向量已经被"删除"——在逻辑上从存储里移除——而语义内容仍然可逆。

这个数字应该这样读：*软删除不是删除，而残留信息不是边缘性的。* 四分之一的可恢复人名，足够做重识别。

**删除的三个层级，以及各自真正保证了什么。**

*逻辑删除。* 设 `deleted_at`，从查询里排除。对字节什么都不保证。只在数据不是个人数据时合适。

*物理删除。* 移除行和向量；重建索引。保证主存储里没了。不保证备份、副本、缓存或事件日志里没了。

*可证明的删除。* 产出证据，证明任何能访问系统的人都无法恢复这些数据。要么验证性地销毁每一份副本（难，因为必须先枚举副本），要么**密码学擦除**——每条记录用一把独立密钥加密，然后删掉密钥。密文可以留着；它不可解。

**密码学擦除是唯一能扩展的方法**，也是 W3C 记忆互操作讨论正在收敛到的方法。工程上是成熟的（逐记录信封加密、密钥删除、密钥登记簿审计）。没普及的原因是成本：它让每次读取都变成一次解密，也让密钥管理成为一等系统。

**没人实现过的结构性修法。** 把*载荷*和*索引*分开，于是删除是载荷存储上的单一操作，而索引只持不透明 ID。那么被删除的条目留下一个什么都解析不到的 ID。这是把海马索引结构（[01-human-memory.zh-CN.md](01-human-memory.zh-CN.md) 第 3 节）用在隐私上：索引存地址不存内容，而一个没有所指的地址不是泄露。它也构造上解决了 ghost vector 问题，因为向量存储里没有内容可逆。

**产品的现实。** [03-agent-native-memory.zh-CN.md](03-agent-native-memory.zh-CN.md) 里每个产品实现的是第一层。豆包的开关关掉时"停止新记忆、停止使用已有记忆，但不删除它们"。Devin 的记忆开关"不删除已有笔记"。两者都诚实，两者都意味着用户的心智模型是错的。

## 7. 租户隔离

隔离失败是最具破坏性的一类，因为它们静默且不加区分。

**三种失败模式。**

*共享索引加应用层过滤。* 一个漏掉的 `WHERE`、一次重构、一条忘了租户的新代码路径——任何一个都会泄露。这是主流架构，也是主流事故。

*后过滤召回坍塌，作为一种安全 bug。* 一个有意思的双重身份：丢掉召回的那个后过滤（[05-infrastructure.zh-CN.md](05-infrastructure.zh-CN.md) 第 3 节），也意味着一个带高选择性租户过滤的查询，可能返回完全没经过过滤的全局 top-k 条目——前提是过滤逻辑在不同代码路径上施加得不一致。

*共享嵌入作为侧信道。* 即便逻辑隔离正确，一个共享的向量索引也让仅有自己分区查询权限的攻击者可以探测几何——时序、邻居数、相似度分数都会泄露他看不见的条目的信息。

**真正能隔离的。**

数据库强制的行级安全是最强的实用选项：策略由引擎施加，所以应用忘不掉。每租户一个 collection 更强，但扩展到消费级租户数不行。共享 collection 加过滤高效，但要求一种组织可靠地维持不住的纪律。

**不太舒服的建议。** 对个人记忆，即便付出代价也在存储层隔离。泄露的失败模式是无界的；更重的存储设计的失败模式是一张账单。

## 8. 供应链

三个 2024 年几乎不存在、现在已上线的面。

**记忆导入。** Claude 和 Kimi 都支持从其他 AI 服务导入记忆。这是一条直接把攻击者此前投毒的一切搬进新系统的通道，而新系统会把它当作自己的历史。

**共享记忆仓库。** Letta 的共享记忆仓库和 Qwen Code 仓库里的 `team-memory/` 意味着记忆随 `git clone` 一起走。一个恶意提交现在也是一次记忆注入，而评审流程是针对代码调的，不是针对读起来像普通偏好的 `MEMORY.md` 条目调的。

**agent 到 agent。** A2A 不共享记忆，所以唯一的路径是一条消息，接收方把它存下来。来源在那一跳丢掉，随之丢掉的是"这条事实来自哪个 agent 的上下文"的能力。

**唯一能推广的缓解。** 在每个边界穿越处——导入、克隆、消息——把记忆当作不可信输入，并且重新推导来源而不是继承它。OpenHands 的包装是正确的模式；差距在于几乎没有别人这么做。

## 9. 政策与敏感数据类别

记忆是个人数据，法规适用。已上线产品里有两个实践值得照抄。

**敏感类别的处理。** Claude 的记忆默认排除一组话题——健康、种族、族裔、宗教、政治、性别认同——仅在明确选择加入后才保存。有些数据即使用户要求也从不保存：政府证件号码、犯罪记录、金融账户号码、移民身份。Kimi 拒绝身份证号、银行卡号、犯罪/受害记录，以及自伤内容。豆包不主动存证件号、家庭住址、银行卡号、密码。

设计原则：**对"记错了比不记更糟"的类别，用默认拒绝清单。** 这不是合规勾选框；这是关于代价不对称的一个正确先验。

**始终用户可见、用户可编辑。** 所有被调研的产品都给出一个可编辑可删除的列表。这在若干法域是监管要求，在所有地方都是正确性要求——用户看不见的记忆，是用户改不了的记忆。

**删除权碰上软删除。** 一个用户对"删除只是逻辑删除"的系统行使删除权，他的权利没有被履行，而 Ghost Vectors 量化了留下多少。这是当前实践与当前法律之间的差距，而且不小。

## 10. 一个你能实施的威胁模型

八条控制，按回报排序。

**1. 每次写入时、从摄取通道处，就打上来源。** 不是事后推断。字段记录源 URL 或会话 ID、通道类型（用户消息 / 工具输出 / 文档 / 其他 agent / 导入）、时间戳。这是其余一切的前提。

**2. 携带权威层级，绝不让记忆变成指令。** 至少两级，而且检索路径必须区别渲染它们。这是 [03-agent-native-memory.zh-CN.md](03-agent-native-memory.zh-CN.md) 第 1 节的信任层级，也是防止一条投毒记忆变成政策的那个控制。

**3. 把注入的记忆包成不可信。** 每一次、每一个提示。代价是一个标签，换来的是模型对待内容方式的改变。

**4. 让写入由授权把关，而不是由可用性把关。** 哪个组件可以写、写到哪个作用域。子 agent 只读；只有根写。导入要过审。

**5. 送出之前校验引用。** 如果一条记忆声称有来源，去查它。证据没了的记忆，就是不该被信任的记忆。

**6. 过期，并且要活下来必须被验证。** 一个带正向验证信号的 TTL，是唯一能自动移除未验证毒药的 lifecycle。

**7. 逐条加密；删掉密钥。** 唯一能挺过备份的删除。

**8. 在引擎层隔离。** 行级安全或每租户 collection。永远不要应用层的 `WHERE`。

## 11. 真正没解决的

四个问题，只说，不给解。

**规模上的可证明删除。** 密码学擦除对载荷有效，对索引结构无效。一条被删除的条目在 HNSW 图里的邻域还在，虽然它比载荷弱得多，但没有人发表过它泄露多少的界。

**通过整合的投毒。** 种下一条记忆的攻击者可以影响一个后台批次对另外许多条的重写。没有防御存在，而这个攻击比直接投毒更糟，因为它在离线发生并产出看起来合理的摘要。

**跨 agent 的来源。** A2A 的不共享记忆规则阻止了问题，也阻止了解法。没有"这条事实来自 agent B，B 又是从用户 C 那里得到的"这种标准，也没有接收方核验它的机制。

**事后检测一条被投毒的记忆。** 来源告诉你它从哪来；引用校验告诉你证据还在不在。两者都不告诉你一条同时通过两者的记忆是不是*假的*。一条写得自信、来源正确、看起来合理、恰好是错的记忆，用今天生产里的任何机制都无法与真的区分开——而 `The Epistemics of Agent Memory`（arXiv:2609.33013）提示 LLM 评判者也分辨不出（判定质量与下游有用性之间 ρ = −0.24）。

最后这一条是诚实的底线。记忆系统可以被做得抗注入、删除正确、隔离严格。它们还不能被做得*真实*，而再多的来源追踪也修不了这一点。
